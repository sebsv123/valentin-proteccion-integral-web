## Corrección de código

Un solo camino **de la aplicación** para los CTA modificados: `trackCommercialCta`
push a dataLayer; nunca gtag directo, fetch analítico ni doble despacho. Conserva
la firma de trackWhatsAppClick para sus callers y adapta las dos variantes de los
helpers de extranjeros y WhatsAppLink. Los CTA principales de las guías usan los
mismos componentes. No añade observadores globales ni modifica otros eventos.

Contrato del objeto:

```
{ event: 'vpi_cta_click', cta_type: 'whatsapp' | 'google_forms',
  page_path: <ruta pública exacta permitida o /other>, product_slug: <código o null> }
```

`google_forms` significa **clic de intención hacia /start**, no formulario externo
renderizado ni enviado. Solo se instrumentan los enlaces controlados y sus
activaciones normales; una visita directa a /start o copiar el enlace no equivale
a ese clic. No se instrumentan respuestas externas.

Se revalida consentimiento al hacer clic, incluso si GTM ya quedó cargado; rechazo,
sin decisión, almacenamiento inaccesible y formatos futuros desconocidos no emiten.
No se acumulan clics previos al consentimiento. Con aceptación puede inicializarse
la cola antes de que termine de cargar el GTM existente. Las rutas y productos son
catálogos exactos; no se copian query, fragmento, href, teléfono, texto de WhatsApp,
UTMs, labels libres, identidad o respuesta. `product_slug=null` limpia el valor
anterior de GTM si no se conoce producto. Se pierde detalle en rutas fuera de catálogo
intencionadamente; no se infiere producto o información personal desde una URL libre.

GTM mantiene sus disparadores automáticos actuales: esta PR no los desactiva ni
publica etiquetas. Tras el cambio, el contenedor actual sigue preparando Contactar
en el stream antiguo y la señal nueva queda en dataLayer **sin etiqueta GA4 propia**.
Por tanto, corregir el emisor no certifica que GA4 reciba el evento nuevo.

## SEO: decisión de no modificar

GET de las cuatro páginas de estudios y residencia no lucrativa ES/EN: HTTP 200,
titles/descriptions coherentes con su contenido y canonical correspondiente.
La búsqueda web muestra residencia no lucrativa con el título específico y texto
sobre requisitos/consulado. Es una muestra de búsqueda, no una SERP de Google
controlada por país/dispositivo ni las consultas reales de GSC.

Las 64 impresiones/posición 6,7/0 clics aportadas no prueban por sí solas un snippet
incorrecto. Sin acceso a consultas/SERP comparable no hay evidencia para escoger
una mejora concreta: **cero cambios de title/description, canonical/hreflang, guías,
navegación o sitemap**. No se reabre indexación de las tres páginas señaladas.

## Validación

- TypeScript, build, lint y regresiones CI existentes, incluido metadata renderizada.
- Seis pruebas nuevas: consentimiento/SSR/errores de storage, emisión única con y
  sin gtag, callers existentes, rechazo posterior sin replay, exclusión de datos
  libres y reconocimiento de rutas /start ES/EN. Integradas en CI.
- Chromium: matriz de 39 clics en siete páginas y tres estados de consentimiento;
  un objeto por clic aceptado, ninguno rechazado/sin decisión, cero gtag directo,
  POST o errores JS. El transporte GTM se sustituye en esta matriz para aislar código.
- Prueba separada con el contenedor público real: confirma stream y coexistencia
  de su Contactar heredado, con hits bloqueados; no se enviaron eventos a GA4.
- Ocho redirects /start verificados mediante GET manual sin seguir a Google Forms.
  Ningún formulario enviado, modificación externa o nuevo proveedor.
- Preview/CI remotos se informan en la PR. Un Preview READY protegido no demuestra QA
  de navegador: si la autenticación impide acceder, se registra el bloqueo.

Reproducir QA de navegador con el servidor de producción local en ejecución:
instalar Playwright en un directorio temporal (sin cambiar dependencias del repo),
y ejecutar `scripts/validate-commercial-cta-browser.mjs` con `VPI_PLAYWRIGHT_MODULE`
apuntando a su index.mjs, `VPI_CHROMIUM_PATH` al ejecutable y `VPI_QA_BASE_URL` a localhost.
No usa tokens ni elude protección de Preview. `VPI_QA_REPORT` permite guardar solo
la matriz de rutas/códigos, sin datos de clientes.

Referencias técnicas: [dataLayer de Google](https://developers.google.com/tag-platform/tag-manager/datalayer)
y [configuración de eventos](https://developers.google.com/analytics/devguides/collection/ga4/events).
No se accedió a GTM Admin, Tag Assistant conectado, DebugView o GA4 Admin en esta sesión.
